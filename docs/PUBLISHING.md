# Publishing and registry review

The distribution path is a public GitHub source repository, a tagged release, and a submission to the reviewed Paseo registry. Publishing a GitHub release or opening an intake issue does not itself mean registry approval.

- Source: https://github.com/ketitongxue/paseo-menubar
- Releases: https://github.com/ketitongxue/paseo-menubar/releases
- CI: https://github.com/ketitongxue/paseo-menubar/actions/workflows/check.yml
- Official submission form: https://github.com/getpaseo/plugins/issues/new?template=submit-plugin.yml
- Official review policy: https://github.com/getpaseo/plugins/blob/main/REVIEW.md

## Publication inputs

The Git artifact includes the readable native Swift source and its checked, generated TypeScript copy, both runtime entries, local modules, English and Chinese overviews, a native-interface PNG, and security documentation. Runtime code has no npm dependencies beyond Paseo-provided SDK modules and Zod, so installation needs no npm preparation command or separate runtime dependency tree. `package-lock.json` locks the development and test tools only.

The native application is compiled locally on activation from reviewed source using the already installed Apple Command Line Tools. Nothing downloads or installs those tools automatically. The native compile command, environment whitelist, generated plist, cache permissions, and subprocess lifecycle are in `server/native.ts`, `server/bridge.ts`, and `native/main.swift`.

The interface image is generated by `npm run screenshot`: a temporary copy of the real native menu receives synthetic tasks and captures only its own AppKit view. The capture is captioned to identify the sample data. There is no full-desktop capture, accessibility automation, production daemon connection, or credential access.

## Release procedure

1. Use Node >=22.12 and npm 11.19.1, then run `npm ci --ignore-scripts`, `npm run check`, and `npm pack --dry-run --ignore-scripts`. npm 10's optional-platform handling is incompatible with this development tree; both CI Node versions explicitly use the declared npm version.
2. On a graphical Mac, regenerate and inspect `assets/menubar-preview.png` if the interface changed.
3. Inspect the exact staged file list. Exclude `node_modules/`, `.research/`, native caches, user configuration, account data, real task data, private paths and logs. Use a GitHub noreply author address.
4. Push source to the public repository and require the corresponding CI jobs to pass. CI checks macOS and Linux with Node 22 and 24; native and GUI-boundary IPC tests skip explicitly on Linux.
5. Create an immutable `v<package version>` tag and GitHub release. Record the full commit SHA and matching CI run.
6. Run `npm run smoke:install -- <full-commit-SHA>` to install the public Git URL on an isolated 0.15.0-beta.1 test daemon. It enables plugins only in a temporary home, disables providers, runs no model turns, and checks `running`, live initialization, native process lifetime and cleanup. It does not reuse or restart the production daemon. The CLI defaults to the installed desktop app; `PASEO_TEST_CLI` can point at a matching test CLI.
7. Open the official submission with the `submission` label and the plugin name as the title. Supply the immutable Git source, categories, media URL, CI link, supported platforms, external compiler requirement, data access and bootstrap limitation. Suggested categories: Utils, then Daemon management.
8. Follow the bot-created review PR. Respond with reviewed fixes when needed. Only report marketplace publication after the approved record is merged and the public directory serves it.

Future Git updates need a new review of the desired commit; they do not automatically follow repository HEAD. Never move an already submitted tag or bypass the official review process.
